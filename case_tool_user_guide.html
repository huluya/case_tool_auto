2. 需求与功能汇总

用例数据Excel 自动识别表头、列数、合并单元格、删除线；用例编号自动生成。
版本管理版本编辑、唯一命名、编辑模式拖动排序、版本副本和独立测试结果。
表格能力列显示/隐藏、拖动排序、默认整理、自定义列、固定操作列。
编辑执行单击直接编辑、双击大文本编辑、执行结果随时可改、批量删除。
富文本图片备注中粘贴图片、缩略图预览、删除、点击/双击放大及拖动查看。
协作安全管理员/测试账号、项目与版本删除密码、数据库备份、权限区分。
核心使用思路：项目负责隔离业务，版本负责隔离测试基线；同一项目下可复制版本形成新的回归范围，源版本的测试结果仍独立保留。

4. 项目和版本管理

4.1 项目

  1. 点击项目列表的“新建”，输入项目名称后保存。
  2. 点击项目名称展开或收起版本列表。
  3. 开启“编辑模式”后，将鼠标移到项目上，使用“编辑”或“删除”。删除项目会同时删除其版本、用例和图片，操作前会要求密码。
  4. 点击任意项目下的版本，可直接切换到该版本；页面会同步刷新列设置、用例列表、统计数据。

4.2 版本

  • 点击“新建版本”创建版本；同一项目内版本名不能重复。
  • 编辑模式下拖动版本左侧的拖动手柄即可排序，松开后自动保存。
  • 编辑模式下右键版本，选择“创建版本副本”，输入副本名称并二次确认。
  • 版本名称可在编辑模式中修改；删除版本需要密码 000000。
推荐基线方式：先将已完成测试的 1.1.1 复制为 1.1.2，再在 1.1.2 中补充新用例。两个版本的用例、执行结果、合并关系和图片相互独立，便于分别回归和追踪。

5. Excel 用例导入

5.1 导入步骤

  1. 先选择目标项目和版本，点击“用例导入”。
  2. 将 .xlsx 或 .xls 文件拖入区域，或点击上传。
  3. 系统以 Excel 第一行作为表头，自动按实际表头数量生成/匹配列。
  4. 确认导入结果和用例数量，关闭导入窗口即可。

5.2 表头识别

下列表头会自动映射为系统列：用例编号、模块、标题、前置条件、操作步骤/步骤、预期结果、优先级、执行结果、备注。未匹配的表头自动创建为自定义列；非系统列可在编辑模式下转为系统列。

5.3 特殊格式

  • 用例编号为空时按导入顺序自动生成 1、2、3……；也可在列设置中“重置编号”。
  • Excel 中同一列的纵向合并单元格会被识别并还原到用例列表中。
  • Excel 单元格的删除线文字会保留，导入后仍显示横线。
  • 第一行表头不能有空列或重复表头；空白数据行会跳过，但合并范围内的空行会保留。
建议导入前确认第一行是完整表头，并避免在表头中间留空列。导入是追加操作，不会覆盖目标版本中已有的用例。

6. 列设置

点击顶部“列设置”打开设置面板。系统列默认顺序为：用例编号、模块、标题、前置条件、操作步骤、预期结果、优先级、执行结果、备注。

操作使用方式
显示/隐藏勾选需要显示的列，未勾选列不会出现在列表和编辑弹窗中。
拖动排序拖动列设置项改变顺序；自定义列也参与排序，不会被一键整理删除。
一键整理点击“一键整理（恢复默认排序）”，只整理已勾选的系统列；未勾选系统列跳过，自定义列保持并继续参与整体顺序。
重置编号在“用例编号”系统列项中点击，将当前版本按列表顺序重新编号为 1～n。
重置测试结果在“执行结果”系统列项中点击，将当前版本所有用例改为“未执行”。操作前有确认提示。
自定义列点击“添加自定义列”创建；编辑模式下可将自定义列转换为系统列。
只想看某个项目的“标题、执行结果、备注”时，保留这三列的勾选并保存即可。列设置是项目级配置，会作用于该项目下的版本。

7. 用例编辑与删除

7.1 新增和编辑

  • 点击“新增用例”创建用例；编辑弹窗中的字段跟随当前列表已显示的列。
  • 编辑模式下单击普通单元格即可直接输入；双击单元格打开大文本编辑弹窗。
  • 直接编辑完成后失去焦点或按回车保存；多行内容可使用 Ctrl+Enter 保存，大文本框支持 Ctrl+Enter。
  • 执行结果可直接在状态下拉框中选择，不依赖编辑模式。
  • 操作列固定在表格最后；前面列较宽时通过表格横向滚动条查看操作列。

7.2 多选删除

  1. 打开编辑模式，勾选表头复选框可全选当前页，也可逐行勾选。
  2. 点击“批量删除（数量）”。
  3. 确认后系统删除所选用例，同时清理关联图片和合并关系。
批量选择按当前列表页生效；删除不可恢复，请确认选择范围后再操作。

8. 合并与取消合并

  1. 开启编辑模式，点击“合并单元格”。
  2. 在同一列选择连续用例的起始和结束单元格。
  3. 系统保存合并关系并在列表中按一个单元格显示，内容垂直、水平居中。
  4. 需要拆开时点击“取消合并”，再选择已合并单元格。

合并信息保存在数据库中，刷新页面或重新登录后仍然有效；删除参与合并的用例时，系统会同步更新或移除无效合并关系。

9. 图片和删除线

9.1 备注内嵌图片

  1. 在新增/编辑用例或大文本编辑框中，将光标放到备注需要插入的位置。
  2. 直接按 Ctrl+V 粘贴图片；也可使用“从剪贴板粘贴图片”。
  3. 图片会显示缩略图，保存后存储为该用例的图片记录，并保留在文字内容中。
  4. 点击或双击缩略图可放大，放大后可滚轮缩放、拖动查看，点击关闭。
  5. 在编辑内容中删除图片后保存，系统会同步删除图片记录及数据库中的图片本体。

图片推荐放在“备注”中，以实现文字与图片穿插的效果；列表中会直接显示备注内图片。

9.2 删除线文字

  • 导入 Excel 时自动识别单元格删除线。
  • 新增/编辑用例时，选中文字后点击“删除线”，或按 Ctrl+Shift+X。
  • 删除线格式会随内容一起保存，并在列表中保留。

10. 版本副本和测试结果重置

10.1 创建版本副本

编辑模式→右键源版本→创建版本副本→输入唯一名称→二次确认

副本复制源版本的用例编号、模块、标题、前置条件、操作步骤、预期结果、优先级、执行结果、备注、自定义字段、排序、合并关系和图片。复制完成后新版本与源版本独立保存。

10.2 重置测试结果

进入目标版本的“列设置”，在“执行结果”行点击“重置测试结果”。确认后当前版本所有用例状态变为“未执行”，源版本不会受到影响。

11. 用例总结逻辑

点击顶部“总结结果”查看当前版本的执行概况。系统以当前版本为统计范围，不跨项目、不跨版本。

统计项逻辑
总用例当前项目、当前版本的用例总数。
各状态数量分别统计“通过、失败、未执行、阻塞、跳过”的用例数量。
状态百分比状态数量 ÷ 总用例数 × 100%，保留 1 位小数。
已执行当前逻辑为：总用例 − 跳过 − 阻塞；只有未执行数量为 0 时才允许总结。
阻塞原因列出阻塞用例；若备注有内容，将备注作为阻塞原因显示。
跳过原因列出跳过用例；若备注有内容，将备注作为跳过原因显示。
可总结条件当前版本总用例数大于 0，且未执行数量为 0。
建议：执行前先复制一个版本作为测试基线；测试结束后确保未执行为 0，再打开“总结结果”查看通过、失败、阻塞和跳过情况。

12. 安全与可行性

12.1 数据到底保存在哪里

位置保存内容是否实时写入
MySQL 数据库项目、版本、列配置、用例文字、执行结果、排序、合并关系，以及图片本体、文件名、类型和用例关联关系。是。文字和图片均在业务操作成功后写入数据库。
backups 文件夹点击“数据库备份”后生成的数据库快照，优先为 SQL 文件，未安装 mysqldump 时为 JSON 文件。否。只有手动点击备份才生成，不会随每次编辑自动更新。
重要结论：新上传和粘贴的图片本体与用例数据一起保存在 MySQL 中，数据库备份会一并包含图片。系统不再创建或依赖 uploads 文件夹。

12.2 备份与恢复建议

  1. 在管理员账号下点击“数据库备份”，选择备份目录或使用默认 backups 目录。
  2. 备份并恢复 MySQL 数据库，图片本体会随数据库快照一起恢复。
  3. 恢复后抽查项目、版本、用例、执行结果、合并单元格和备注图片，确认图片本体可以正常读取。

安装 mysqldump 时，系统生成带时间戳的 SQL 数据库快照，并使用单事务参数减少备份过程中的数据不一致；由于图片本体已存入 MySQL，SQL 快照会同时包含图片数据。未安装时会降级导出核心业务表 JSON，该方式不适合作为包含图片的完整恢复备份。

12.3 安全可行性评估

方面当前措施评估与建议
账号权限管理员与测试账号分离；测试账号不显示备份、项目和版本管理操作。适合基础内部使用；正式环境建议使用更复杂密码并按人员分配账号。
危险操作项目/版本删除需要 000000 和二次确认；批量删除、重置编号、重置结果也有确认提示。能降低误操作风险；正式环境建议修改删除密码并避免多人共用管理员账号。
数据一致性用例文字、图片本体及图片关联关系统一通过数据库保存。图片随数据库备份恢复，不依赖外部图片目录。
备份安全支持手动 SQL/JSON 快照并可指定目录。当前不是自动、实时、异地备份；建议定时复制到另一块磁盘或受控存储，并设置保留周期。
恢复演练提供数据库快照文件。建议定期在测试库执行恢复演练，确认 SQL、图片和版本结果均可恢复。
敏感信息数据库连接配置由部署环境配置。不要把数据库密码或备份文件暴露到公网；生产环境应限制数据库权限并使用 HTTPS。
适用结论：当前方案适合单机或内网测试团队使用，能够满足项目、版本、用例和图片的日常管理。若用于生产或多人长期协作，应补充自动定时备份、异地/离线副本、备份加密和恢复演练。

13. 数据库类型与技术栈

层次技术/组件用途
前端结构HTML5、CSS3、原生 JavaScript页面布局、表格交互、编辑模式、拖拽、弹窗、图片预览。
后端服务Python Flask提供登录、项目、版本、用例、导入、图片、备份和统计接口。
数据访问Flask-SQLAlchemy / SQLAlchemy通过 ORM 操作项目、版本、列、用例、合并和图片记录。
数据库MySQL，字符集 utf8mb4保存业务数据、版本结果、列配置、合并关系和图片元数据。
Excel 处理openpyxl读取工作表、表头、单元格样式、删除线及合并范围。
图片存储MySQL 图片本体 + 关联数据新上传和粘贴的图片本体、类型、文件名及所属用例均保存于数据库；历史文件图片保留兼容读取。
接口形式HTTP REST 风格 JSON API前端通过异步请求刷新局部数据，避免整页刷新。

新图片与用例数据统一存储在数据库：删除用例或版本时，系统会同步删除图片本体和数据库记录。

14. 与传统 Excel 用例的区别

对比维度传统 Excel用例管理平台
数据组织文件、工作表、文件名管理，容易出现多个版本副本。项目—版本—用例分层，版本和测试结果独立保存。
多人协作依赖文件传递或共享盘，容易覆盖和产生冲突。数据集中存储，按账号和权限进入同一系统。
列管理手动插列、隐藏列、调整宽度和顺序。列设置可显示/隐藏、拖动排序、自定义列和一键整理。
导入成本需要手工整理表头和合并内容。第一行自动识别列；系统列自动映射，自定义列自动生成，合并/删除线可识别。
执行结果通常手工填写颜色或文字，统计需要公式。状态统一管理，实时计数、百分比和总结条件自动计算。
图片内容图片常作为浮动对象或单独附件，文字关联不稳定。备注中可穿插图片，图片本体与关联关系统一由数据库管理。
历史追踪依赖另存为多个文件，难以确认基线。版本副本保留用例、结果、图片、合并和排序，便于回归。
误操作保护主要依赖文件权限和人工备份。项目/版本删除密码、数据库备份和删除二次确认。

15. 常用操作速查

目标操作路径
导入新用例选择项目 → 选择版本 → 用例导入 → 上传 Excel
改变列表字段列设置 → 勾选显示列 → 拖动排序 → 保存
恢复系统列顺序列设置 → 一键整理（恢复默认排序） → 保存
重排用例编号列设置 → 用例编号 → 重置编号 → 确认
清空当前版本执行结果列设置 → 执行结果 → 重置测试结果 → 确认
复制版本编辑模式 → 右键版本 → 创建版本副本 → 输入名称 → 二次确认
编辑长文本编辑模式 → 双击单元格 → 大文本编辑框
粘贴图片备注编辑框中定位光标 → Ctrl+V → 保存
多选删除用例编辑模式 → 勾选用例 → 批量删除 → 二次确认
数据库备份管理员登录 → 数据库备份 → 输入目录或使用默认目录
数据安全提示：项目、版本和用例删除属于不可恢复操作；执行批量删除、重置结果前，请确认当前项目和版本无误，必要时先完成数据库备份。
